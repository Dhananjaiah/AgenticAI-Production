1. Open the repository and activate Python

UBUNTU TERMINAL
cd ~/src/agentic-ai-40days
source .venv/bin/activate
python --version
python -c "import sys; print(sys.executable)"

What this doesMoves into the course repository, activates its virtual environment, and prints the Python version and executable.

Why we do itAll paths and imports in this demo assume the repository root and its own Python environment.

Pass: Python is 3.11 or newer and its path contains .venv.

2. Compile both scripts without calling a provider

SYNTAX CHECK

python -m py_compile phase-1-foundations/day-03/labs/lab-3.B-loop-over-questions/solution/ask_many.py

What this doesAsks Python to parse and compile both solution files.

Why we do itThis catches syntax and indentation errors without sending data, using a key, or making a paid model call.

Pass: both commands finish without output or an error.

3. Inspect the function-based sorter

OPEN LAB 3.A
code phase-1-foundations/day-03/labs/lab-3.A-review-sorter-with-functions/solution/sorter_functions.py

4. Test every action path locally

DECISION UNIT TEST
python -c "import runpy; m=runpy.run_path(r'phase-1-foundations/day-03/labs/lab-3.A-review-sorter-with-functions/solution/sorter_functions.py'); flag=m['flag_if_complaint'];
for sentiment in ('positive','negative','unclear'):
 result={'sentiment':sentiment,'topic':'test','summary':'test'}; print(sentiment,'->',flag(result))"

What this doesLoads the real action function and calls it with three controlled dictionaries.

Why we do itThe routing rule does not need a model. This fast test proves the if/elif/else paths independently.

Pass: positive → ok, negative → complaint/support, unclear → human check.

6. Inspect the question loop

OPEN LAB 3.B

LOCAL BATCH SIMULATION

8. Read one useful Python error

FORCE A SMALL, SAFE ERROR
python -c "print(unknown_name)"

What this doesRuns a one-line program that uses an undefined name.

Why we do itThe error names the exact missing value. Read that first useful line before changing code.

FIX ONLY THE NAMED PROBLEM
python -c "known_name='fixed'; print(known_name)"

What this doesDefines the variable before printing it.

Why we do itA focused correction followed by the same kind of check is the basic debugging loop.
