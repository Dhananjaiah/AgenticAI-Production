A useful program can read almost like instructions: load the reviews, classify each review, choose an action, keep the result, and print the summary. Small functions hide details while clear names show the main story.
Variables and strings

Give values useful names.

review = "Stopped charging after two days" sentiment = "negative" answered = 0

= assigns

Put this value under this name.

Quotes mean text

A Python string holds characters.

A variable gives a value a useful name. The equals sign assigns a value to that name. Text values are strings and use quotes. Clear names such as `review`, `result`, and `action` explain their purpose.
F-strings

Build text from values.

prompt = f"Classify this review: {review}" print(f"Answered {answered} of {len(questions)}")
Insert data into text. Do not execute untrusted text as code.
An f-string lets us place a value inside text with curly braces. We use it to build prompts and readable output. The value is inserted when the line runs. Never place an untrusted value into a command and execute it as code.
Functions

A function is a named recipe.

def classify(review): answer = ask(...) return extract_json(answer) result = classify(review)
A function wraps steps under one name. Parameters are its inputs, and `return` sends a result back. The function should do one clear job. A good name tells the reader what that job is.
Type hints

Make the contract visible.

def classify(review: str) -> dict: ... def flag_if_complaint(result: dict) -> str: ...
Hints explain intent. Important runtime boundaries still need validation.
In `classify(review: str) -> dict`, the hint says the function expects text and returns a dictionary. Type hints improve reading and tool support. Python does not automatically validate every hint at runtime, so important boundaries still need real checks.
Dictionaries

Use labels to reach values.

result = { "sentiment": "negative", "topic": "charging", "summary": "Stopped charging quickly" } print(result["sentiment"])
A dictionary is a group of labelled values. Our classified result has labels such as sentiment, topic, and summary. Code reads a value using its key. A missing key raises an error, so validated input matters.
Lists

Keep many items in order.

reviews = [ "Arrived early and works.", "Stopped charging.", "Setup is confusing." ] results = [] results.append(result)
A list holds several values under one name. Square brackets create the list, and positions start at zero. We can ask for its length and append new results to the end.
Loops

Write the process once.

for review in reviews: result = classify(review) results.append(result)
Three items or three hundred: the loop shape stays the same. Outside calls still need limits.
A `for` loop takes each item from a list and runs the indented block once. The same code can handle three reviews or three hundred, although outside calls still need limits, cost control, and error handling.
Conditions

Choose exactly one path.

if sentiment == "negative": return "send to support" elif sentiment == "unclear": return "human check" else: return "ok"
= assigns. == compares.
An `if` statement asks a yes-or-no question. `elif` checks another case, and `else` handles everything left. Double equals compares values. A single equals sign assigns a value.
Put it together

One clear step per line.

for review in reviews: result = classify(review) action = flag_if_complaint(result) results.append(result) print(result, action)
For each review, call the classify function, pass the result to the action function, append the result, and print it. Each line has one purpose. The detailed provider call stays inside `classify`.
Finished workflow

Classification plus action.

positive | delivery | Arrived early action: ok negative | charging | Stopped charging action: COMPLAINT — send to support unclear | product | No clear opinion action: human should check
The finished script prints the sentiment, topic, summary, and action for each review. A negative result goes to support. An unclear result goes to human review. Other results are marked okay.

Lab 3.B

Skip bad input before a call.

for number, question in enumerate(questions, start=1): if not question.strip(): print("skipped") continue answer = ask(question) answered += 1
The questions list contains one blank item on purpose. `enumerate` gives a number and question on each pass. The condition detects blank text. `continue` skips the rest of that pass, preventing an unnecessary model call.

Production boundary

A loop can multiply outside risk.

Calls

Count them.

Cost

Latency

Failure

Handle each item.

A loop around a provider call can multiply latency and cost. Add input limits, timeouts, failure handling, and concurrency control before using large batches. Type hints and clean functions improve code, but they do not replace validation, tests, authorization, or monitoring.
